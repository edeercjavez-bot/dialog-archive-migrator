# 对话存档迁移器

把 AI 对话的导出数据，整理成一份能接着玩的存档。

解析 DeepSeek 导出的压缩包，合并多个账号的记录，沿主线回溯丢掉废稿，剔除思考链，最后生成一段可以直接丢给新对话的「前情提要」。

## 它解决什么问题

换模型、换账号、或者想重新开一局的时候，新对话不记得之前发生过什么。

手动复制几百条历史记录有两个问题：一是 token 烧得厉害，二是容易漏掉关键设定——上一章的伏笔、NPC 的态度、背包里还剩什么。

这个工具把导出数据整理成一份结构化的前情提要，让新对话能立刻接上，而不是从「你好，请介绍一下自己」重新开始。

## 功能

| 能力 | 说明 |
|---|---|
| **多账号合并** | 一次拖入多个 `.zip` 或 `.json`，按对话 ID 自动去重，按更新时间倒序排列 |
| **免解压** | 官方导出的压缩包直接拖进来，新旧两种导出格式（`conversations.json` / `chat_sessions/` 逐会话文件）都能识别 |
| **大包也不卡** | 解压和解析都是流式的，几百 MB 的包也不会整份读进内存 |
| **只保留主线** | 沿 `current_node` 往回走，重新生成产生的废弃分支会被丢弃 |
| **剔除思考链** | 默认剥离 `THINK` 片段和内联 `<think>` 标签，可手动开关 |
| **自定义称呼** | 把「玩家 / AI」改成你的角色名，存档读起来不出戏 |
| **指令模板** | 文游 GM / 语C 单角色 / 小说续写 / 通用对话四套开头指令，正文拼法完全一致 |
| **保留设定** | `system` 消息不再丢弃，以【设定】标注输出，可在界面上开关 |
| **勾选筛选** | 全选 / 反选 / 取消，支持标题搜索（按 `/` 快速定位） |
| **两种输出** | 续玩用的前情提要 `.txt`，或精简的合并 `.json`；多条合并时指令只出现一次 |

## 快速开始

### 在线使用

部署完成后访问你的 Pages 地址即可，无需安装任何东西。

### 本地使用

下载 `index.html`，双击用浏览器打开。整个工具就这一个文件，没有构建步骤，也不需要联网。

仓库里的 `demo-sample.zip` 是一份脱敏的示例数据（故意保留了废弃分支和内联思考链），拖进去就能看到清洗效果。

## 使用流程

### 电脑

1. 登录 DeepSeek 网页版，从头像进入「设置 → 数据管理 → 导出数据」，拿到一个压缩包
2. 把压缩包拖进页面（不用解压）
3. 左侧勾选要保留的对话，右侧实时预览
4. 复制，或下载成文件

### 手机

手机上可以直接完成清洗，几百 MB 的包也不会把页面撑爆。**导出这一步仍然建议在电脑上做**，手机端操作路径长、容易出错。

拿到压缩包之后：

1. 用微信「文件传输助手」把它发到手机
2. 在手机上打开部署好的网址
3. 点上传，把文件选进来

不同系统略有差异：

- **iOS**：在微信里点开压缩包 → 右上角 `···` →「用其他应用打开」→「存储到“文件”」。然后网页点上传，选「选取文件」，在「文件」App 里找到它
- **Android**：先从微信保存到「文件管理」或下载目录，网页上传时从文件管理器选择

> 手机上不要直接双击 `index.html`。iOS 的「文件」App 预览 HTML 不会执行脚本，页面会是白的。手机请走部署后的网址。

## 输出是什么样

「续玩格式」会在开头加上一段系统指令，要求接手的 AI 先输出进度存档卡，再紧接最后一幕继续：

```
【系统指令：对话存档迁移与前情提要生成】
请仔细阅读下面我与前任 GM 的历史存档……

【玩家】
我往森林方向走。

──────────────────────

【GM】
晨雾还没散，村口的老槐树滴着水。
背上的行囊比想象中沉，铁剑的鞘已经磨出了毛边。

========== 历史存档结束 ==========
```

「纯净对话」则只保留正文和称呼，适合归档收藏。

开头的系统指令有四套模板，按用途选：**文游 GM**（带存档卡与可选行动）、**语C 单角色**（先复述关系记忆再续接）、**小说续写**（梳理人物与线索后接着写）、**通用对话**（整理结论、待办、约束与已排除方案）。除了这段指令，其余拼法完全一致。

## 隐私

所有解析都在浏览器里完成。

没有服务器，没有账号体系，没有上传。你选的文件从头到尾都没离开过这台设备，断网也能正常使用。

中间结果存在浏览器的 IndexedDB 里，刷新页面会自动清空，不会留在这台设备上。

## 技术实现

单文件、零依赖，没有构建步骤。

- **自己解 ZIP**：只读文件尾部的中央目录，再按偏移切出需要的那一条，配合浏览器原生 `DecompressionStream('deflate-raw')` 增量解压。整个压缩包从头到尾不会被读进内存
- **边解压边切分**：一个只跟踪字符串状态和花括号深度的扫描器，把 `conversations.json` 按顶层元素逐条切开；每切出一条就单独 `JSON.parse`、清洗、落库，随即丢弃原文。因此不需要把整份 JSON 拼成一个字符串，也绕开了浏览器对单个字符串的长度上限
- **正文不常驻内存**：清洗后的对话按条写进 IndexedDB，界面上只保留轻量索引；切换对话时只读取那一条。写入前会用 `navigator.storage.estimate()` 预先估算剩余空间
- **导出时重建结构**：把保留下来的消息重建成一条线性 `mapping` 链，既去掉了废弃分支，也兼容依赖该结构的解析器

## 常见问题

**拖入压缩包没反应？**

确认文件是 DeepSeek 官方导出的 `.zip`，而不是手动压缩的包——手动压缩的目录层级不同，可能找不到 `conversations.json`。

**手机上传时找不到文件？**

iOS 需要先把文件「存储到“文件”App」，微信里直接点开是看不到的。Android 请从下载目录选。

**导出的 JSON 导入别的工具不认？**

导出的是按原格式重建的对话结构（含 `mapping`、`current_node`、`fragments`）。不同工具对格式的宽容度不一样，建议先拿一条对话试。

**支持 ChatGPT 或其他平台的导出吗？**

目前只针对 DeepSeek 的导出结构做了适配。ChatGPT 的结构比较相近（同样是 `mapping` + `current_node`），可能能用，但没有测试过，不保证结果正确。

**对话很多会不会卡？**

解析是流式的，内存占用基本不随包体增长。实测解压后 300 MB（约 7,900 个对话、12 万条消息）的处理在 1 秒量级，浏览器会慢一些，峰值内存约 150 MB——改造前同样的数据要 900 MB。

手机上处理几百 MB 的包，瓶颈通常不是内存而是本地存储：写入前会先用 `navigator.storage.estimate()` 估算剩余空间，不够会提前提示你分批导入，而不是写到一半失败。
